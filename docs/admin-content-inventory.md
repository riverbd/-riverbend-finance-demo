# Riverbend Admin — Complete Editable-Field Inventory

Generated by inspecting the source of truth: `src/admin/store.tsx`,
`src/admin/AdminDashboard.tsx`, and every component that calls `useContent()`.

**Scope:** 106 content leaf fields + 4 customer-data editor surfaces.
This is the pre-integration baseline. Nothing here is proposed — it is what
exists today.

---

## Where content is stored today

| Store | localStorage key | Read by | Written by |
|---|---|---|---|
| Website content | `riverbend_content_v5` | `src/admin/store.tsx` → every consumer | `setContent` / `resetContent` |
| Customer data | `riverbend_accounts_v4` | `src/account/auth.tsx` | admin mutators |
| Admin session | `riverbend_admin_v5` | `src/admin/store.tsx` | `loginAdmin` |

Content is saved **wholesale** (`setContent(c)`) and exported/imported as one
JSON document in the Data tab.

## C. Customer data editors (account data, not content)

| Tab | What it edits | Current write path |
|---|---|---|
| **Users** | *Read-only* table: fullName, username, email, checking, savings | none |
| **Balances** | Per customer: `checking`, `savings` (2 inputs each) | `setUserBalance` → localStorage |
| **Cardholders** | Per card: `cardholderName` (1 input per card) | `setCardholderName` → localStorage |
| **Credentials** | Per customer: `username`, `password`, `memberId`, `email` (4 inputs) | `setAccountCredentials` → localStorage |

Cardholders renders `network · •••• last4 · expires expiry` once per card.
`fullName`, `initials`, `memberSince`, card `label`/`last4`/`network`/`expiry`/`frozen`
have **no** admin editor.

## D. Findings that need a decision

1. **`account.cards.expiresLabel`** — editable in the dashboard, never displayed
   (`Cards.tsx:93` hard-codes "Valid thru").
2. **`account.login`** — `submittingLabel` is displayed but has **no editor**;
   `successLabel` has neither.
3. **`brand`** — displayed in 5 places, has **no editor**.
4. **Passwords** — `CredentialsEditor` sets a password, but the schema
   deliberately has no password column. Persisting it to Supabase would
   contradict the earlier constraint. Credentials split: username/email/memberId
   → Postgres; password stays device-local until Supabase Auth.
5. **`TopBar` / `AccountShell`** hard-code "RIVERBEND" rather than reading
   `brand.name`, so renaming the brand would not update the nav.

Items 1–3 and 5 are pre-existing gaps. Per instruction they are preserved as-is,
not "fixed", unless you want them addressed.
